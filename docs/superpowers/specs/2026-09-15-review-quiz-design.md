# 复习库 + 单词检测 — 设计

日期：2026-09-15
状态：已实现（2026-09-18 修订 §4 出库规则 + 新增 §4.2 管理面板）
改动文件：`build_html.py`、`test_page.mjs`

---

## 1. 目标

在现有《四六级词汇背诵清单》里加两件互相咬合的事：

1. **复习库**——收「我不熟的词」，能进能出，自我清理
2. **检测**——用户自定义题数，从指定范围抽题考，答错自动回填复习库

两者不是独立功能。**检测答错 → 进复习库；出库由用户在管理面板自己决定**（原文是「复习库答对 → 出复习库」，2026-09-18 已废止，见 §4）。这个联动才是价值所在。单独的「随机抽题给个分」是一次性娱乐，考完什么都不剩。

## 2. 范围

**做**：复习库、★ 控件、检测（两种题型 + 混合）、搜索长条重构、结果页

**不做**（明确排除）：

- 间隔重复算法（SRS）、连续答对 N 次才出库
- 「错次/对次」计数器——状态保持 `Set`，不升级成 `Map`
- 独立「收藏夹」——和复习库混在一起会让出库规则和统计都含糊
- 跨设备同步——单文件 + localStorage 的固有限制，是独立问题
- 首字母/字母数提示——实测只能把冤判从 0.7% 降到 0.4%，收益 0.3% 却等于剧透

## 3. 数据与状态

```js
cet_vocab_mastered_v1   // 现有，不动。Set<小写词头>，驱动进度条
cet_vocab_review_v1     // 新增。Set<小写词头>，复习库
cet_vocab_day           // 现有，不动
cet_vocab_theme         // 现有，不动
```

复用现有的 `keyOf = w => w.w.toLowerCase()`，两个库同一套 key。

**零迁移**：不碰 `mastered` 的结构和语义，现有 60 项断言不受影响。

★（在复习库）和 ✓（已掌握）**保持独立**，互不干扰。理由：★ 记录「我这次没想起来」，✓ 记录「这个词我过了」，本来就是两件事。代价是会出现「✓ 且 ★」的组合，视觉上用颜色区分（✓ 绿 / ★ 金）。

## 4. 复习库的进出

> **2026-09-18 修订**：下表最后一行「检测答对（该词在库中）→ 出库」以及其下的「循环自我校正」理由**已废弃并删除**。
> 现状：**复习库只能由用户手动出库**——卡片 ★、管理面板的行内 ✕、管理面板的「清空复习库」。
> 唯一例外见 §4.1。

| 事件 | 动作 |
|---|---|
| 检测答错 | 进库 |
| 检测答错 → 点「我写对了」 | 改判为对；**只撤销本次入库**（见 §4.1） |
| 卡片上点 ★ | 进库 |
| 卡片上再点 ★ | 出库 |
| 检测答对（该词在库中） | **留在库里**，结果页明写一句提示 |

**为什么答对即出库，而不是「连续答对 N 次」**（原理由，已废弃）：出库规则不是在断言「他真的会了」，而是在把复习库的定义从「历史不熟的词」改成「当前不熟的词」。如果出库出错了，这个词会在下一次全表检测时再次答错 → 自动回库。**循环自我校正**，不需要计数器，状态才能保持 `Set`。

**为什么这条理由站不住**（改的依据）：上面那句「下一次全表检测时再次答错 → 自动回库」依赖「下一次全表检测会抽到这个词」。
按本 spec §5 自己的算术：从全表 5271 抽 20 题，命中某个特定词的期望是 `20 × 1/5271 ≈ 0.38%`。
所以误删一个词之后它**实际上再也回不来**——「循环」在真实的抽题密度下不存在，
这条规则净效果是让复习库随机漏词，而不是自我校正。
加上用户现在有管理面板可以自己删，自动删就成了纯粹的风险来源。

### 4.1 申诉的边界（唯一保留的自动出库）

`appeal()` 里必须**只撤销「本次答错顺手入库」的那一条**，靠 `it.addedByAnswer` 判别；
**本来就在库里的词不许动**——那个词在库里的原因是用户之前手动的 ★，与这次误判无关，撤销它等于替用户做决定。

```js
if (it.addedByAnswer && review.has(k)){ review.delete(k); it.addedByAnswer = false; saveReview(); }
```

### 4.2 管理面板

头部 `★ 复习库` 按钮 → 复用 `.dialog` 骨架的面板 `#rev`（与检测配置共用一块 `#mask`）。
列表按**全表原序**（天序）排，每行给「词 / 音标 / 释义 / 第 N 天 / ✕」；
点行 → 关面板并 `goto(i)` 跳到那天那张卡；点 ✕ → 出库但**不关面板**（方便连着删）；
「清空复习库」走**两段式确认**（第一次点变文案 + `armed` 样式，3 秒后自动复位），
**不用 `confirm()`**——jsdom 不实现它，`test_page.mjs` 的 virtualConsole 会把它过滤成 `undefined`，那条路径会变成永久测试盲区。
面板里**没有**「测复习库」按钮（用户明确排除）；要考复习库走 `▣ 检测` 选范围。


## 5. 检测流程

```
点「检测」→ 配置面板
    范围：复习库（默认）/ 全部 / 已掌握
    题数：输入框，默认 20，上限 = min(范围内词数, 200)
    题型：看中文写英文 / 看英文写中文 / 混合
  → 逐题作答（全屏模式）
  → 结果页：总分 · 分题型得分 · 错题列表 · 「只重测错题」· 「再测」
```

**抽题**：从范围内**无放回随机**抽 N 个词。只考主词 `w`，不考派生词。

**混合题型**：每题独立 50/50 随机二选一。结果页分题型统计得分。

**复习库为空时**：范围选「复习库」且库为 0 词 → 「开始」禁用，提示「复习库是空的，先背几天或选其它范围」。

**为什么默认抽复习库**：复习库 30 词时，从全表 5271 抽 20 题，期望命中 `20 × 30/5271 ≈ 0.11 个`——要连考 9 次才见到 1 个复习库的词。默认抽全表等于复习库不存在。

## 6. 判分规则

### 6.1 通用

用户输入与答案都先经 `norm()` 归一化再比较：

```js
const normEn = s => s.toLowerCase().replace(/[^a-z]/g, '');
const normCn = s => s.replace(/[\s,.。，、；;:：!！?？"'“”‘’()（）]/g, '');
```

### 6.2 拼写题（看中文写英文）

**题干** = `w.cn` 的完整释义（多个义项全列，不做截断）。
**答案集** = 从 `w.w` 展开（派生词 `w.deriv` 不进答案集，理由见下）：

1. 基础：`normEn(w.w)`
2. 含括号 `A(B)C`（48 个，如 `afterward(s)`）→ 追加 `normEn(A+C)` 与 `normEn(A+B+C)`
   → `afterward(s)` 接受 `afterward` 和 `afterwards`
3. 含斜杠 `A/B`（69 个，如 `airplane/aeroplane`）：
   - 追加 `normEn(A)`
   - 若 `B` 以 `-` 开头（如 `authorize/-ise`）→ 追加 `normEn(A.slice(0, A.length - B.length + 1) + B.slice(1))`
     → `authorize/-ise` 接受 `authorize` 和 `authorise`；`celsius/-cius` 接受 `celsius` 和 `celcius`
   - 否则追加 `normEn(B)`

**派生词不进答案集**——不是「判错」，是压根不在答案集里，无需反馈特判、无需解释。

理由：题干含词性前缀（`vt.` / `n.` / `a.`，**99.8% 的词条都有**），已经排除了派生词——`creation` 是 n.，对不上题干的 `vt.`。用户不可能往那儿填。**拼写题的答案是唯一确定的，判分就是 `normEn(输入) ∈ 答案集`。**

**残留歧义实测 0.6%**（14 组 / 29 词）：完整释义（含词性）当题干时，只有这些词共享题干：

| 组 | 性质 |
|---|---|
| `check` / `check/cheque`、`fuel` / `fuel(l)`、`fulfil(l)` / `fulfil`、`story` / `stor(e)y`、`gasoline/petrol` / `petrol` | 同一个词的不同变体写法，§6.2 的展开规则已覆盖大部分 |
| `anyhow`/`anyway`、`cargo`/`goods`、`everybody`/`everyone`、`expressway`/`freeway`/`motorway`、`I`/`me`、`our`/`ours`、`their`/`theirs`、`us`/`we`、`who`/`whom` | 真同义词 |

抽 20 题的期望冤判 ≈ `20 × 0.0055 ÷ 2 ≈ 0.06` 次。可忽略。

### 6.3 认义题（看英文写中文）

**题干** = `w.w`（大字）+ 朗读按钮。**不给音标**——音标对「想起中文」没有帮助，只占地方。

**答案集** = 从 `w.cn` 切分：

1. 去词性前缀 `^[a-z]+\.\s*`
2. 去括号内容 `（...）` / `(...)`
3. 按 `[,，;；、]` 切分成义项列表，去空白
4. 用户输入若含分隔符 → 拆开，**任一义项命中即判对**

### 6.4 「我写对了」申诉

两种题型都有（**同一个组件，不按题型分叉**——为拼写题特判「不显示申诉按钮」反而更多代码）。按下后：改判为对、不进库、不参与错题统计。

拼写题保留它只是兜那 0.6% 的残留歧义，顺手带上，**不是必需品**。

**认义题上它是必需品**——判分靠字面命中，而人的表达是自由的。实测例子：`crew` 的词库义项是「全体人员, 一群人, 全体队员」，用户写「船员」会被判错，但没错。

**部分匹配提示**（**仅认义题**）：判错时若用户输入与某义项共享 ≥2 个连续汉字（如「爬行」与「爬」共享「爬」），反馈里直接点明「你写的『爬行』与义项『爬』部分匹配」，**引导用户申诉，而不是默默判错**。这是防复习库被冤判词灌满的主要手段。

拼写题不做部分匹配提示——它的编辑距离没有意义（`crcket` 与 `cricket` 共享 6 个字符，但那只是打错字，不是另一种正确写法）。拼写题只给申诉按钮。

## 7. UI 规格

### 7.1 列表页

- **搜索长条**：替换原 32×32 的 🔍 图标按钮（触控目标建议 ≥44px，32px 在手机上偏小）。整行 40px，在 header 内（header 已 `sticky`，所以滚下去也能搜）。输入即浮出下拉结果（`position:absolute`，不推挤内容）。点结果 → 跳到那天 + 高亮 + 清空。`/` 快捷键改为聚焦此框。
- **检测按钮**：header 右上，带文字的 `▣ 检测`，不是第二个小图标。沿用「图标太小不好点」的意见。
- **复习库按钮**（2026-09-18 加）：`★ 复习库`，紧挨检测按钮，开的是 §4.2 的管理面板。**按钮上不显示词数**（库大小一直在变，数字会让固定头部里的按钮宽度抖动）。
- **窄屏**：头部 4 个控件在 ≤380px 时折成 3 行，不横向溢出。
- **复习库计数**：`head-meta` 行右侧显示「复习库 N 词」。
- **卡片控件**：右侧 `.ctl` 容器，`★` 在左、`✓` 在右。★ 用 `aria-pressed` 表状态，`title` 在「加入复习库 / 从复习库移除」间切换。在库中的卡片加 `.inreview` 类（金色描边）。
- **已知代价**：header 从 ~78px 涨到 ~118px 吸顶。

### 7.2 检测配置面板

复用原搜索用的 `.panel` / `.mask`（原搜索改为常驻长条后，这块弹层正好回收给检测）。

### 7.3 答题页

全屏模式，逐题。题干上方有 `第 N 题 / M` + 进度条 + 退出。

反馈区三态：对 / 错 / 错+申诉。答错时立即显示正确答案。

### 7.4 结果页

- 总分 + 正确率 + 用时 + 范围 + 题型
- **分题型得分**（拼写 x/y、认义 x/y）——两种题型判分可信度不同，混在一起算总分是在平均两个不同尺度的东西
- 错题列表（带题型标签，已全部加入复习库）
- 一句提示：**答对的词仍留在复习库，不会自动移出**（原文这里是「答对并从复习库移出」清单 + 「撤销移出」，2026-09-18 已删）
- 「只重测这 N 个错词」/「再测 M 题」

## 8. 已知代价与风险

| 项 | 说明 |
|---|---|
| 认义题判错率系统性偏高 | 语义对、字面没命中。**看正确率时以拼写题那半边为准** |
| header 变高 | 手机上滚到第 20 个词时顶部被吃掉 ~118px |
| ✓ 与 ★ 可并存 | 视觉上可能别扭，语义上是有意的（见 §3） |
| 长期不用会积压 | **库是单调增长的**（2026-09-18 起只有用户手动出库）。不主动去管理面板清，它只增不减。这是拿「不会误删」换来的代价 |
| 检测得分 ≠ 掌握度 | 题干给出中文/英文本身就是提示，是「再认」不是「回忆」。**答错很可信，答对不太可信** |

## 9. 验证

```powershell
cd .
python build_html.py     # 重新生成 HTML
node test_page.mjs       # 现有 60 项断言 + 新增断言，必须全过
```

新增断言至少覆盖：

- 点 ★ → 词进 `cet_vocab_review_v1`；再点 → 出
- 检测答错 → 该词进复习库
- 复习库中答对 → **仍留库**，且结果页没有「撤销移出」按钮
- 申诉 → 本次入库的那条被撤销；**本来就在库里的词不动**
- 管理面板：列表 == 库内容且按全表原序；行内 ✕ 出库且不关面板；点行跳转到该词所在天；清空需两次点击
- 判分：`afterward` 与 `afterwards` 都算对 `afterward(s)`；`authorise` 算对 `authorize/-ise`
- 判分：认义题写任一义项算对；写部分匹配的（共享 ≥2 字）判错但带提示
- 范围/题数/题型三个配置项生效
- 复习库为空时「开始」禁用

手动验证：双击 `out/四六级词汇背诵清单.html`，跑一遍完整检测流程。

**注意 jsdom 的坑**（见 `CLAUDE.md`）：`matchMedia` 需要 shim；`save()` 有 220ms 防抖，断言前要等 300ms；`.card` 的 DOM 顺序 ≠ 原始序号顺序。
